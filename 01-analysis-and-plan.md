## 1. Что такое Moodle и зачем нужна альтернатива

### Что делает Moodle

Moodle (Modular Object-Oriented Dynamic Learning Environment) — самая распространённая в мире open-source LMS: установлена в 240+ странах, ~2000 плагинов в маркетплейсе, актуальная версия — Moodle 5.0 (апрель 2025) с поддержкой до октября 2026, в разработке 5.2/5.3.

Ядро Moodle обеспечивает:

- **Структуру обучения**: сайт → категории → курсы → секции → активности и ресурсы.
- **Активности (mod/\*)**: Assignment, Quiz, Forum, Lesson, Workshop, SCORM, H5P, Chat, Glossary, Wiki, Database, Choice, Feedback, BigBlueButton, LTI External Tool.
- **Ресурсы**: File, Folder, Page, URL, Book, Label.
- **Question Bank**: 15+ типов вопросов, импорт/экспорт в GIFT, Moodle XML, IMS QTI 2.0, XHTML.
- **Gradebook**: оценки, шкалы, категории, формулы, итоговые оценки.
- **Роли и капабилити**: тонкая RBAC-система (Student, Teacher, Manager, Site admin + кастомные).
- **Записи на курсы**: ручная, самозапись, когорты, LDAP, платная (PayPal/Stripe-плагины).
- **Web Services API**: единый endpoint `webservice/rest/server.php`, сотни функций (`core_user_get_users_by_field`, `core_enrol_get_enrolled_users` и т.д.), форматы REST/XML-RPC/SOAP.
- **Backup/Restore**: формат `.mbz` — это `.tgz` (с 2.9), внутри XML по структуре БД.
- **Стандарты**: SCORM 1.2/2004, LTI 1.3 Advantage, xAPI (через плагины), H5P нативно.

### Сильные стороны Moodle

Огромное сообщество, проверенная педагогическая модель, гибкость через плагины, бесплатность, поддержка офлайн-обучения через мобильное приложение, MFA, GDPR/152-ФЗ-совместимые конфигурации при self-host.

### Слабые места (то, что НЕ копируем)

- **Архитектура** — монолит на PHP, тянется с 2002 года, тяжело масштабируется, рендеринг страниц медленный.
- **UX** — выглядит как админка из 2010-х, неинтуитивен для преподавателей-новичков, мобильный опыт слабый.
- **Расширение через плагины на PHP** — высокий порог входа, плагины ломаются между мажорными версиями.
- **API** — RPC-стиль с сотнями функций, нет нормального OpenAPI, неудобно интегрировать с современными SPA/мобильными приложениями.
- **Тяжёлый деплой** — нужен LAMP-стек, cron, отдельный воркер для очередей, файловое хранилище.
- **Отчётность и аналитика** — базовые, для серьёзных дашбордов нужны платные модули или внешние BI.
- **AI-фичи** прикручены сверху в 5.0, не нативно.

### Почему есть смысл делать своё (Парта5)

**Целевая аудитория уточнена:** средние общеобразовательные школы и учреждения дополнительного образования в РФ. Это госсектор и муниципалитет, закупки по 44-ФЗ/223-ФЗ.

1. **Школьный рынок РФ массово сидит на Moodle** — потому что он бесплатный и self-host. Платные SaaS (Skillspace, iSpring Learn, Teachbase, МТС Линк Курсы) ориентированы на корпоративное обучение, а не на средние школы. Это ниша слабо занята.
2. **Тривиальный self-host** — главная причина живучести Moodle в школах. Школьный сисадмин (часто учитель информатики) должен поднять сервер одним `docker-compose up`. Это критичный признак.
3. **Реестр отечественного ПО + 152-ФЗ обязательны** — иначе школа не сможет купить, а УДО — не сможет включить в бюджет.
4. **Интеграции с гос-системами обязательны:** ФГИС «Моя школа», ЕСИА (Госуслуги) для логина учителей и родителей, синхронизация оценок с электронными дневниками (Дневник.ру / ЭлЖур / Сетевой Город).
5. **UX проще Moodle на порядок.** Учитель должен собрать первый урок за 15 минут без чтения мануала.
6. **Родительский кабинет — обязательный модуль** в MVP, не «потом». В РФ это запрос №1 после оценок.
7. **Геймификация и визуальный прогресс** важны для младшей и средней школы (значки, уровни, прогресс-бары).
8. **API-first / headless** — современные интеграции (мобильные приложения, Telegram-боты, AI-ассистенты с RAG) делаются за часы.
9. **AI-native** — встроенный авто-генератор тестов из материалов, авто-проверка эссе, AI-тьютор по курсу с RAG, авто-конспекты видео. Реальный отличительный признак.

### Бизнес-модель: open-core

- **Бесплатное self-host ядро** под лицензией **MPL 2.0** (не AGPL — она убивает интеграторов; не Apache — она позволяет конкуренту закрыть форк). Школы и УДО ставят бесплатно — это даёт массовое распространение.
- **Платное облако (SaaS)** для школ, которым не нужен self-host → попадает в реестр отечественного ПО → продаётся через тендеры.
- **Коммерческая лицензия для интеграторов** — кто хочет ставить школам и обслуживать без открытия модификаций.
- **Платные модули** поверх ядра — прокторинг, AI-генерация контента, региональная аналитика для управления образования.

Аналог: GitLab CE/EE, Penpot, Outline.

## 2. MVP-функционал (по результатам твоего выбора)

Все четыре направления, что ты выбрал, входят в MVP. Декомпозиция:

### 2.1 Курсы, уроки, контент

- Иерархия: Организация → Курс → Модуль → Урок → Блок контента.
- Типы блоков: заголовок, текст (rich-editor/TipTap), список, изображение, видео (self-hosted HLS), видео-embed (YouTube/RuTube/VK/Kinescope/Vimeo/Boomstream), файл, выноска (callout), код, цитата, разделитель, generic iframe (для админов). H5P — отдельным интеграционным блоком в Phase 5.
- Версионирование курсов (draft / published).
- Шаблоны курсов и копирование.
- Программы (последовательности курсов, цепочки сертификации).

### 2.2 Тесты и задания

- Типы вопросов в MVP: одиночный выбор, множественный выбор, true/false, короткий ответ, сопоставление, числовой, эссе (с ручной проверкой), пропуски (cloze).
- Банк вопросов на уровне организации и курса.
- Настройки попыток: лимит времени, число попыток, перемешивание, прохождение порога.
- Задания: текстовый ответ, загрузка файлов, дедлайны, ручная оценка с комментариями, рубрики.
- **Импорт из Moodle XML / GIFT** — критично для миграции.

### 2.3 Прогресс и аналитика

- Трекинг на уровне блока (xAPI-like statements внутри).
- Дашборд ученика: % прохождения, дедлайны, оценки.
- Дашборд преподавателя: воронка по курсу, проблемные блоки (где буксуют), скорость прохождения.
- Дашборд админа: активность, retention, NPS.
- Экспорт в CSV/Excel.

### 2.4 Коммуникация и сообщество

- Комментарии к урокам и заданиям (треды).
- Уведомления: email + Telegram (нативно, не плагином) + push в PWA.
- Объявления в курсе.
- Чат с преподавателем (1-на-1 в MVP, групповые форумы — позже).

### 2.5 Родительский кабинет (обязательно в MVP для школ)

- Привязка родитель ↔ ученик (один родитель — несколько детей).
- Дашборд: успеваемость, активность, дедлайны, замечания.
- Уведомления о новых оценках и пропусках через Telegram/email.
- Сообщения учителю.

### 2.6 Гос-интеграции (обязательно для школ)

- **ЕСИА (Госуслуги) OAuth** — логин учителей и родителей. У школьников чаще нет ЕСИА → внутренние аккаунты + привязка через классного руководителя.
- **ФГИС «Моя школа»** — выгрузка/сверка журналов оценок.
- **Электронные дневники** (Дневник.ру / ЭлЖур / Сетевой Город) — синхронизация оценок и расписания (на чтение и опционально на запись).

### 2.7 Что НЕ входит в MVP (фаза 2+)

Workshop (peer review), Wiki, Glossary, BigBlueButton-интеграция, маркетплейс курсов, прокторинг, региональная аналитика, мобильное нативное приложение (PWA достаточно), белые лейблы.

## 3. Рекомендуемый стек

### Рекомендация: **Next.js 15 (App Router) + tRPC + Postgres + Prisma + S3-совместимое хранилище**

Это твой основной стек, ты в нём силён, и для headless LMS он реально подходит.

**Плюсы:**

- Один язык на фронт и бэк → быстрая итерация.
- App Router + Server Components → меньше клиентского JS, лучше для SEO лендингов курсов.
- tRPC → типобезопасный API без OpenAPI-боли (но при необходимости легко обернуть в REST/OpenAPI для внешних потребителей).
- Prisma → быстрые миграции, удобная работа с моделью данных.
- Лёгкий деплой: Vercel/Railway/own VPS + managed Postgres.
- Интеграция с AI-провайдерами (OpenAI, Anthropic, локальные LLM через Ollama) — нативно через твой стек.

**Минусы:**

- При >100k активных учеников придётся выносить тяжёлые фоновые задачи (видео-транскодинг, генерация отчётов, AI) в отдельные воркеры (BullMQ + Redis).
- Server Actions ещё имеют острые углы.

### Альтернативы и когда их выбирать

| Стек                                  | Когда выбирать                                                                        | Минусы                                    |
| ------------------------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------- |
| **FastAPI + Postgres + React**        | Если хочешь тяжёлую ML/аналитику в ядре, плотную работу с Pandas/NumPy                | Два языка, два деплоя, больше boilerplate |
| **NestJS + Postgres + Next.js фронт** | Если планируешь команду >5 backend-разработчиков и нужен enterprise-like монолит с DI | Избыточно для старта                      |
| **Микросервисы с нуля**               | НЕ выбирать. Преждевременная оптимизация.                                             | Год на инфраструктуру вместо продукта     |

### Дополнительные компоненты

- **Видео**: self-hosted в ядре. Загруженные mp4 идут через FFmpeg-воркер (BullMQ) → HLS (360p/720p/1080p, master.m3u8 + сегменты) → S3 → клиент через HLS.js. Это нужно для self-host философии «как Moodle, но современно» — школа разворачивает у себя, никаких внешних SaaS не требуется. Плюс универсальный embed-блок (YouTube/RuTube/VK/Kinescope/Vimeo/Boomstream/Дзен) для тех, кто не хочет хранить видео локально. Адаптеры коммерческих SaaS (Kinescope, Boomstream, PlatformCraft, Yandex Cloud Stream) — опциональные модули в маркетплейсе, не обязательная зависимость ядра.
- **Файлы**: S3 API — Yandex Object Storage / VK Cloud / MinIO (self-host).
- **Очереди**: Redis + BullMQ.
- **Поиск**: PostgreSQL FTS на старте, Meilisearch при росте.
- **Email**: SMTP через Unisender Go / Mailopost (российские).
- **Telegram**: bot API напрямую (у тебя уже опыт).
- **Аутентификация**: Auth.js (NextAuth) + 2FA через TOTP. SSO через OIDC/SAML — для enterprise-фазы.
- **AI-слой**: OpenAI API + Anthropic API + Ollama локально, Pinecone или pgvector для RAG (pgvector — проще, в той же БД).
- **Аналитика событий**: PostHog (self-host) или ClickHouse, если нужна тяжёлая аналитика по `learning_event`.

### Стандарты, которые нужно поддержать с самого начала

- **LTI 1.3 Advantage** — обязательно для интеграции внешних инструментов (H5P, симуляторы, прокторинг). Это OIDC + JWT (RS256) + OAuth 2.0 + сервисы AGS/NRPS/Deep Linking.
- **SCORM 1.2** — для импорта legacy-контента корпоративных клиентов.
- **xAPI / cmi5** — нативно как формат внутренних learning-событий. cmi5 = современный преемник SCORM, поддержанный DoD; разделяет роли LMS (записи) и LRS (прогресс).
- **H5P** — встроить через `@lumieducation/h5p-server` (Node-порт core H5P, MIT-лицензия). Это даст 50+ типов интерактивного контента из коробки.
- **Moodle XML / GIFT / QTI 2.0** — на чтение, для импорта банков вопросов.

## 4. Модель данных (минимальный набор сущностей)

```
Organization (тенант)
  ├── User (role: admin/teacher/student)
  ├── Course
  │     ├── Module
  │     │     └── Lesson
  │     │           └── ContentBlock (type: text/video/quiz/assignment/h5p)
  │     ├── Enrollment (User ↔ Course)
  │     └── QuestionBank
  │           └── Question (type: mcq/saq/essay/match/numeric/cloze)
  ├── Quiz
  │     ├── QuizQuestion (ref to Question, weight, order)
  │     └── Attempt
  │           └── Response
  ├── Assignment
  │     └── Submission (files, text, grade, feedback)
  ├── LearningEvent (xAPI-like: actor, verb, object, result, timestamp)
  ├── Thread / Comment
  └── Notification
```

Учитывай: `LearningEvent` — append-only, скорее всего вынести в отдельную таблицу с партициями по месяцам или в ClickHouse при росте.

## 5. Стратегия миграции из Moodle

Ты выбрал миграцию **контента курсов + банков вопросов** (без пользователей и истории прогресса). Это сильно упрощает задачу.

### 5.1 Источники данных

| Что мигрируем                                 | Формат                                            | Способ извлечения                                    |
| --------------------------------------------- | ------------------------------------------------- | ---------------------------------------------------- |
| Структура курса (секции, активности, ресурсы) | `.mbz` → `moodle_backup.xml` + `/activities/*/`   | Распаковать tar.gz, парсить XML                      |
| Файлы (видео, PDF, изображения)               | `/files/<hash[0:2]>/<contenthash>` + `files.xml`  | Маппинг `contenthash` → `filename` через `files.xml` |
| Банк вопросов                                 | Export → **Moodle XML** (рекомендуется) или GIFT  | Через UI Moodle, потом парсинг                       |
| Тесты (quiz)                                  | `/activities/quiz_*/quiz.xml` + ссылки на вопросы | XML внутри backup                                    |
| Задания (assignment)                          | `/activities/assign_*/assign.xml`                 | XML внутри backup                                    |

### 5.2 Пайплайн миграции

1. **CLI-скрипт `mbz-importer`** (Python — для парсинга XML удобнее всего, либо Node с `fast-xml-parser`):
   - Принимает `.mbz` файл.
   - Распаковывает в temp.
   - Парсит `moodle_backup.xml` — определяет курс, секции, список активностей.
   - Для каждой активности парсит XML внутри `/activities/<type>_<id>/`.
   - Маппит файлы из `files.xml` → `/files/<hash>` → грузит в S3.
   - Маппит типы активностей → внутренние блоки:
     - `mod_page` → ContentBlock(type=text)
     - `mod_resource` (PDF/файл) → ContentBlock(type=file)
     - `mod_url` → ContentBlock(type=link)
     - `mod_label` → ContentBlock(type=text)
     - `mod_quiz` → Quiz + QuizQuestions (через questionbank xml)
     - `mod_assign` → Assignment
     - `mod_book` → Module с Lesson'ами
     - `mod_h5p` → ContentBlock(type=h5p) + распаковка `.h5p` пакета
     - `mod_lesson`, `mod_workshop`, `mod_forum`, `mod_wiki` → **flag для ручной адаптации** (либо игнор, либо плейсхолдер)
   - Создаёт сущности в БД через API.
2. **Веб-импортёр** в UI админки: загрузка `.mbz`, превью того, что распознано, выбор что мигрировать, dry-run и потом коммит.
3. **Question Bank импорт отдельно**: эндпоинт принимает Moodle XML / GIFT / QTI 2.0, валидирует, складывает в QuestionBank выбранной организации.

### 5.3 Что точно не мигрируется автоматически

- Сложные форумы (Forum) — концептуально перестроить под Threads.
- Lesson (ветвящиеся уроки) — мигрировать как ContentBlock'и линейно, ветвление руками.
- Кастомные плагины — игнорируем.
- Условные правила доступа (Restrictions) — мигрировать в свою систему правил.

### 5.4 Пилот миграции

Возьми 1 реальный курс из Moodle (например, какой-то демо-курс с moodle.net) → прогоните импортёр → пусть преподаватель проверит, что доехало корректно. Только потом масштабировать.

## 6. Дорожная карта (6 фаз)

| Фаза                            | Срок       | Содержание                                                                                                                                    | Критерий готовности                                                   |
| ------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| **0. Прототип**                 | 2 недели   | Next.js + Prisma + Postgres, базовая модель Organization/Course/User, аутентификация, простая страница курса                                  | Можно создать курс, добавить текст и видео-ссылку, открыть как ученик |
| **1. MVP контент + видео**      | 4–6 недель | Блочный редактор (12 типов), self-hosted HLS видео через FFmpeg-воркер, универсальный embed, прогресс по блокам, publishing flow                | Преподаватель собирает реальный курс RunStart, ученик проходит        |
| **2. Тесты и задания**          | 4–6 недель | QuestionBank, 7 типов вопросов, Quiz с попытками, Assignment с загрузкой, ручная и авто-оценка                                                | Прогон реального теста на 30 учеников                                 |
| **3. Миграция из Moodle**       | 3–4 недели | CLI mbz-importer, веб-UI импортёра, импорт Moodle XML question bank                                                                           | Один реальный курс из Moodle загружен и проходим                      |
| **4. Аналитика и коммуникация** | 4 недели   | LearningEvent, дашборды (ученик/препод/админ), комментарии, уведомления (email + Telegram + push)                                             | Преподаватель видит, где буксуют ученики                              |
| **5. Стандарты + AI**           | 6–8 недель | LTI 1.3 Advantage (как платформа), SCORM 1.2 player, H5P, AI-генератор тестов из материала курса, AI-тьютор с RAG по курсу                    | Сертификация LTI 1edtech, рабочий AI-тьютор                           |
| **6. Школьные интеграции**      | 5–6 недель | ЕСИА OAuth, ФГИС «Моя школа», импорт-экспорт оценок в Дневник.ру/ЭлЖур, родительский кабинет (если не успели в фазе 4)                        | Школа-пилот ведёт реальный класс                                      |
| **7. Готовность к продаже**     | 4 недели   | Мульти-тенантность с биллингом (ЮKassa/CloudPayments), white-label, попадание в реестр отечественного ПО, аудит на 152-ФЗ, ФСТЭК-документация | Продан первый внешний клиент                                          |

**Итого до коммерческой готовности:** ~9–11 месяцев работы при темпе 1 разработчик full-time + Claude. С учётом параллельного ведения RunStart — добавить 30–50%, итого 12–16 месяцев. Это нормальный срок для LMS-продукта, готового к B2G.

## 7. Ключевые риски и как их митигировать

| Риск                                                                | Митигация                                                                                                          |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **Переоценка скорости разработки** — LMS объективно большой продукт | Жёстко резать MVP, не делать форумы/Wiki/Workshop                                                                  |
| **Миграция из Moodle сломается на edge-cases**                      | Поддержать только топ-7 типов активностей, остальное — placeholder с предупреждением                               |
| **Видеохостинг — главная статья расходов**                          | Self-hosted FFmpeg+HLS — нулевая стоимость SaaS, но нагрузка на сервер школы. Для облачного SKU — Yandex Object Storage с CDN |
| **152-ФЗ и попадание в реестр**                                     | Хостинг только в РФ (Yandex Cloud / VK Cloud / Selectel), документация по ИБ с самого начала                       |
| **AI-фичи как differentiator могут не сработать**                   | Не делать их в MVP, добавить после того как ядро стабильно                                                         |
| **Конкуренция со Skillspace/iSpring/Teachbase**                     | Не пытаться обогнать по фичам — выигрывать на API-first, AI-native, open-source-ядре, цене                         |
| **Школы — медленный канал продаж (тендеры, бюрократия)**            | Старт через прямые продажи 5–10 продвинутым школам и УДО (бесплатно self-host), накопление кейсов → потом тендеры  |
| **ЕСИА требует регистрации в Минцифры как ИС**                      | Подавать заявку в Минцифры на регистрацию как ИС класса К2/К3 — это 3–4 месяца, начинать параллельно с разработкой |

## 8. Что делать прямо сейчас

1. **Купить домены:** `parta5.ru` (основной), плюс `parta5.school` и `parta5.app` как защита бренда. ~1500₽ за `.ru` (2 года) + ~$60/год за каждый из двух остальных.
2. **Подать заявку на товарный знак «Парта5»** в Роспатент в классах МКТУ 41 (образование) и 42 (программы для ЭВМ). ~33к госпошлины, защита 10 лет. Без этого имя не защищено.
3. **Зарегистрировать ИП** (если ещё нет) — нужно для попадания в реестр отечественного ПО, для приёма платежей и для договоров со школами.
4. **Найти 1 школу-пилот в Карелии** через связи RunStart / ЗаБег.РФ — это критично, без живого пилота продукт не отвалидируешь.
5. **Поднять репозиторий** (зеркала: GitHub + GitFlic.ru — последний обязателен для реестра ОВП).
6. **Получить реальный `.mbz`** — свой тестовый курс из demo-Moodle или попросить у пилотной школы.
7. **Запустить Фазу 0** (2 недели): Next.js + Prisma + Postgres с мульти-тенантностью с первого коммита.
