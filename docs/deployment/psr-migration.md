# Миграция 106 курсов ПрофСпецРесурса из Moodle в «Парту5» (задача C7)

Статус: инструкция подготовлена в рамках Stage D / задачи S7 (2026-07-29). Скрипты **не
запускались** — весь прогон делает человек по этому гайду. Все факты ниже, отмеченные как
«проверено», получены только чтением на sel1 (`ls`, `find`, `docker inspect`, `SELECT`) —
никаких изменений на боевом Moodle ПСР не вносилось.

Связанные документы: `docs/STAGE-D-SPEC.md` (пункт C7), `packages/importer/src/cli.ts`
(CLI импортёра), `scripts/psr-export-batch.sh`, `scripts/psr-import-batch.sh`.

## 1. Последовательность работ

```
dry-run импорта 4 уже выгруженных курсов (C6)
        │  (проверить, что отчёт "что потеряем" вменяемый, прежде чем распаковывать 106)
        ▼
экспорт остальных ~102 курсов с Moodle ПСР (sel1)
        │  scripts/psr-export-batch.sh, можно волнами/с перерывами — идемпотентно
        ▼
dry-run импорта ВСЕХ 106 курсов
        │  scripts/psr-import-batch.sh --dry-run, сводный отчёт "что потеряем"
        │  — точка принятия решения: если пропуски велики/неожиданны, останавливаемся
        │    и разбираемся ДО реальной записи в БД
        ▼
реальный импорт волнами (например по 10–20 курсов за раз)
        │  scripts/psr-import-batch.sh, resume-friendly, отчёт по каждой волне
        ▼
сверка итоговых чисел с 106 / 2954 / 62942 (раздел 4)
        │
        ▼
разбор расхождений по CSV/MD отчётам, точечный повторный импорт при необходимости
```

### 1.1 Dry-run на уже выгруженных 4 курсах (быстрая проверка конвейера)

```bash
./scripts/psr-import-batch.sh \
  --src-dir /opt/psr/c6-export \
  --school psr --user admin@psr.parta5.ru \
  --dry-run
```

Смотрим `reports/psr-import-dryrun-report.md` — сколько уроков/квизов/вопросов
импортёр реально видит, что попадает в «пропущенные активности» и «пропущенные типы
вопросов». Если тут уже что-то настораживает — останавливаемся и разбираемся, не
доходя до полной выгрузки 106 курсов.

### 1.2 Экспорт оставшихся курсов (на sel1)

```bash
# Сначала — безопасный просмотр плана, ничего не запускает:
./scripts/psr-export-batch.sh --list-only

# Затем реальная выгрузка. Можно ограничивать волну через --limit,
# скрипт сам пропустит то, что уже выгружено (в т.ч. 4 курса C6, если
# положить их в тот же --dest, или начать с чистого /opt/psr/c7-export).
./scripts/psr-export-batch.sh --dest /opt/psr/c7-export --min-free-gb 40
```

Скрипт:

- сам проверяет, что запущен на машине с контейнерами `psr-moodle-1` / `psr-mariadb-1`
  (иначе отказывается работать);
- останавливается, если свободного места меньше порога (`--min-free-gb`, по умолчанию 40 ГБ);
- пишет лог по каждому курсу (id, имя, размер, время, статус) в `DEST/psr-export-batch.log`
  и на экран;
- **безопасен для прерывания**: Ctrl+C / обрыв SSH-сессии не портит уже готовые файлы,
  повторный запуск пропустит то, что уже выгружено, и продолжит с оставшихся курсов.

Если сессия SSH обрывается часто — используйте `screen`/`tmux` на sel1, либо `--limit N`
и запускайте волнами по расписанию (например, по 20 курсов за раз).

### 1.3 Dry-run по всем 106 курсам

```bash
./scripts/psr-import-batch.sh \
```

### 1.4 Реальный импорт волнами

```bash
./scripts/psr-import-batch.sh \
  --src-dir /opt/psr/c7-export \
  --school psr --user admin@psr.parta5.ru \
  --limit 20
```

Повторные запуски той же команды продолжат с того места, где остановились (файл
состояния `SRC_DIR/.psr-import-state.tsv` — по одной строке `<файл><TAB>done<TAB>время`
на успешно импортированный курс). Неуспешные курсы НЕ помечаются как done и будут
повторно обработаны на следующем прогоне автоматически — специально повторять их
руками не нужно, разве что после исправления первопричины ошибки.

Каждый прогон добавляет строки в `reports/psr-import-report.csv` (файл каждый раз
перезаписывается заново для этого прогона — если нужна история всех волн, копируйте
`.csv`/`.md` под другим именем между волнами, например `--report-name wave-1`).

## 3. Что делать при обрыве

- **Обрыв во время экспорта**: файл текущего курса, скорее всего, не был перемещён в
  `DEST` (перемещение — последний шаг после успешного `backup.php`), значит при
  повторном запуске курс попробует выгрузиться заново. Осиротевшие временные файлы в
  `/opt/psr/private/temp/psr-export-batch/` можно удалить вручную — они не мешают
  следующему запуску, но занимают место.
- **Обрыв во время импорта**: текущий курс просто не попадёт в `done` в файле
  состояния — при повторном запуске он обработается заново. Если импорт прервался
  ПОСЛЕ того, как курс частично записался в БД (например, контейнер импортёра убили
  посреди транзакции) — полагаться на атомарность транзакции Prisma
  (`withTenantClient`/`tx` в `import-course.ts`): либо курс целиком закоммитился, либо
  не создался вовсе. Проверить: `SELECT id FROM "Course" WHERE slug = '<ожидаемый-slug>';`
  — если пусто, повторный запуск импортёра безопасен и создаст курс заново.
- **Диск почти заполнился во время экспорта**: скрипт сам остановится по порогу
  `--min-free-gb` ДО следующего курса — уже начатая выгрузка текущего курса может
  доработать. Освободите место (например, удалите то, что уже успешно импортировано и
  проверено — см. раздел 4) и продолжайте `--dest` тем же каталогом.

## 4. Сверка после импорта (SQL к БД «Парты5»)

Через `docker compose exec db psql -U parta5 -d parta5` (или прямое подключение по
`DATABASE_URL`, в зависимости от того, как развёрнут инстанс на момент прогона — см.
`docker-compose.yml` / прод-конфиг из задачи S3):

```sql
-- Курсы школы ПСР (school slug используется в CLI как --school)
SELECT count(*) FROM "Course" c
JOIN "School" s ON s.id = c."schoolId"
WHERE s.slug = 'psr';

-- Квизы школы ПСР
SELECT count(*) FROM "Quiz" q
JOIN "School" s ON s.id = q."schoolId"
WHERE s.slug = 'psr';

-- Вопросы школы ПСР
SELECT count(*) FROM "Question" qq
JOIN "School" s ON s.id = qq."schoolId"
WHERE s.slug = 'psr';
```

Ожидаемые числа для полной сверки — **106 / 2954 / 62942** (см. раздел 0). Точное
совпадение маловероятно на 100%: импортёр по устройству пропускает нераспознанные типы
вопросов и неподдерживаемые активности (см. `report.skippedActivities`,
`report.questions.skippedByType` в `packages/importer/src/report.ts`) — расхождение
нужно сверять со сводным отчётом `reports/psr-import-report.md`, а не считать любое
отклонение багом.

Дополнительно полезно свериться по каждому курсу отдельно:

```sql
SELECT c.title, c.slug,
       (SELECT count(*) FROM "Module" m WHERE m."courseId" = c.id) AS modules,
       (SELECT count(*) FROM "Lesson" l
          JOIN "Module" m ON m.id = l."moduleId"
          WHERE m."courseId" = c.id) AS lessons
FROM "Course" c
JOIN "School" s ON s.id = c."schoolId"
WHERE s.slug = 'psr'
ORDER BY c.title;
```

и сопоставить со столбцами `modules`/`lessons`/`quizzes`/`questions_imported` в
`reports/psr-import-report.csv`.

## 5. Откат неудачного импорта одного курса

Импортёр создаёт для курса: строку `Course` (каскадно тянет за собой `Module` →
`Lesson` → `ContentBlock` → `Enrollment`, см. `onDelete: Cascade` в
`packages/db/prisma/schema.prisma`), ОДИН `QuestionBank` с именем
`Импорт: <shortname исходного курса Moodle>` (см. `packages/importer/src/import-course.ts`,
строка с `tx.questionBank.create`) и вопросы/квизы, привязанные к этому банку и к
courseId только косвенно — через `ContentBlock.data->>'quizId'` у блоков типа `QUIZ`.

Поэтому корректный порядок отката (иначе получите вопросы/квизы-сироты либо ошибку
внешнего ключа):

```sql
BEGIN;

-- 1. Найти курс
-- (slug — тот, что импортёр присвоил курсу; смотрите в CSV-отчёте или
--  SELECT id, slug, title FROM "Course" WHERE title = '<название из Moodle>';)
\set course_id '00000000-0000-0000-0000-000000000000'

-- 2. Собрать id квизов, пока курс ещё жив (после удаления курса ContentBlock
--    исчезнет каскадно, и узнать quizId будет неоткуда)
CREATE TEMP TABLE _rollback_quiz_ids AS
SELECT DISTINCT (cb.data->>'quizId')::uuid AS quiz_id
FROM "ContentBlock" cb
JOIN "Lesson" l ON l.id = cb."lessonId"
JOIN "Module" m ON m.id = l."moduleId"
WHERE m."courseId" = :'course_id'::uuid
  AND cb.type = 'QUIZ';

-- 3. Удалить сам курс (каскадно удалит Module/Lesson/ContentBlock/Enrollment;
--    связанный CourseImport.courseId уйдёт в NULL сам — onDelete: SetNull)
DELETE FROM "Course" WHERE id = :'course_id'::uuid;

-- 4. Удалить квизы (каскадно удалит QuizQuestion/QuizAttempt/QuizResponse)
DELETE FROM "Quiz" WHERE id IN (SELECT quiz_id FROM _rollback_quiz_ids);

-- 5. Удалить банк вопросов этого импорта (каскадно удалит Question —
--    к этому моменту на них уже не ссылается ни один QuizQuestion, иначе
--    сработает onDelete: Restrict и шаг упадёт — это сигнал, что квизы
--    из шага 4 удалены не все)
DELETE FROM "QuestionBank"
WHERE "schoolId" = (SELECT id FROM "School" WHERE slug = 'psr')
  AND name = 'Импорт: <shortname исходного курса Moodle>';

COMMIT; -- или ROLLBACK, если что-то пошло не так на промежуточном шаге
```

Дополнительно (опционально, не обязательно для повторного импорта):

- `FileAsset`, загруженные под картинки вопросов этого курса, автоматически не
  удаляются шагами выше (у `Question` нет `onDelete: Cascade` на файлы) — они станут
  сиротами в БД и в S3. Опознать их надёжно (без риска задеть чужие файлы) можно по
  `uploaderId` = user импорта и `createdAt` в узком окне вокруг времени импорта этого
  курса, сверяясь с `reports/psr-import-report.csv` (столбец с длительностью). Если нет
  уверенности — оставить как есть: место — не критично, а риск случайно удалить чужой
  файл выше пользы.
- После отката не забудьте убрать строку с этим файлом из
  `SRC_DIR/.psr-import-state.tsv` (если она там появилась) — иначе
  `psr-import-batch.sh` посчитает курс уже импортированным и пропустит повторную
  попытку. Строку можно найти по имени `.mbz`-файла и удалить вручную любым
  текстовым редактором — файл строго построчный (`tsv`).

**Не проверено**: реальное поведение шага 5 (Restrict) при частично удалённых
квизах — логика выведена из схемы Prisma (`onDelete: Restrict` на
`QuizQuestion.question`), но на живых данных этот откат не прогонялся (задачей
S7 запуск чего-либо на sel1, кроме чтения, не предусмотрен).
