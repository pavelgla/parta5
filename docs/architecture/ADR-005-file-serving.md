# ADR-005: Раздача файлов школ через авторизованный прокси-эндпоинт

**Статус:** принято
**Дата:** 2026-07-16

## Контекст

`FileAsset` хранится в S3-совместимом объектном хранилище (MinIO в self-host, Yandex Object Storage / VK Cloud в облаке) по ключу `schools/<schoolId>/<assetType>/<uuid>-<originalName>` (см. `packages/storage/src/adapter.ts`, `buildKey`). Эти файлы — учебные материалы, обложки курсов, вложения уроков — часто содержат персональные данные или коммерчески значимый контент конкретной школы.

Обнаружены два связанных бага:

1. `apps/web/lib/file-url.ts` строил URL напрямую из `S3_PUBLIC_URL` + ключ. В `docker-compose.yml` бакет MinIO анонимно раздаёт на чтение только префикс `public/*` (`mc anonymous set download local/${S3_BUCKET}/public/*`). Ключи файлов школ лежат под `schools/<schoolId>/...`, то есть вне этого префикса — прямой GET отдаёт 403. Ссылки на файлы были нерабочими.
2. FILE- и IMAGE-блоки урока (`apps/web/app/(app)/learn/.../page.tsx`) читали `data.key`/`data.url`/`data.filename`, тогда как схема блока (`apps/web/server/schemas/block-data.ts`) хранит `{ fileAssetId, displayName }` / `{ fileAssetId, alt, caption }`. Поля не совпадали независимо от первого бага.

Нужно решить, как раздавать файлы так, чтобы:

- Бакет школ оставался приватным (152-ФЗ — персональные данные; открытие бакета публично разрушает мультитенантность на уровне хранилища, в обход RLS на уровне БД).
- Доступ проверялся по сессии и `schoolId`, как и для остальных данных (см. [ADR-002](ADR-002-multitenancy-rls.md)).
- Ссылка, один раз сохранённая в HTML-контенте урока (TipTap, `data.html`) или в JSON блока, не протухала — presigned URL с TTL, вставленный в сохранённый контент, через несколько часов/дней станет нерабочим.

## Решение

Файлы школ раздаются **только** через собственный авторизованный эндпоинт `GET /api/files/<fileAssetId>`:

- `auth()` (Auth.js, node-side) проверяет сессию; нет сессии или нет `session.user.schoolId` → `401`.
- `FileAsset` ищется через `withTenant(schoolId, ...)` — RLS на уровне БД отсекает файлы чужой школы; `SELECT` с `WHERE schoolId = ...` дублирует проверку на уровне запроса.
- Если запись не найдена или `status !== 'UPLOADED'` (файл ещё не подтверждён или уже удалён) — `404`, **не** `403`: чужой школе не сообщается даже о факте существования файла с этим id.
- При успехе — `302`-редирект на presigned GET-URL, сгенерированный `StorageAdapter.presignDownload(key, expiresSeconds)` на 300 секунд, с `Cache-Control: private, max-age=60`.

Presigned URL генерируется **на лету при каждом запросе** и нигде не сохраняется — ни в `FileAsset`, ни в JSON блока, ни в HTML урока. В коде (блоки, редактор, `<img>`/`<a>`) везде используется стабильная ссылка `/api/files/<fileAssetId>`, которая не протухает, потому что presign происходит заново при каждом обращении.

Бакет S3/MinIO остаётся полностью приватным для префикса `schools/*`. Анонимный доступ (`public/*`) не используется для файлов школ — при необходимости публичного контента (например, публичные лендинги курсов вне LMS) это отдельное явное решение, не связанное с `FileAsset`.

## Рассмотренные альтернативы

| Альтернатива                                                                           | Причина отклонения                                                                                                                                                                                                                                                                                                  |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Сделать бакет школ публичным (расширить `mc anonymous set download` на `schools/*`)    | Прямое нарушение 152-ФЗ (персональные данные доступны без авторизации кому угодно по прямой ссылке) и разрыв мультитенантности на уровне хранилища — RLS в БД защищает записи `FileAsset`, но не сами байты в S3.                                                                                                   |
| Presign URL при рендере страницы/блока и сохранять его в `data` блока или в HTML урока | Presigned URL живёт ограниченное время (обычно минуты-часы). Контент урока (`TEXT.data.html`, JSON блоков) сохраняется в БД и может отображаться спустя дни/месяцы — ссылка к этому моменту протухнет. Требовало бы фоновой job на пере-подпись, что сложнее и менее надёжно, чем генерация на лету при каждом GET. |
| Presign URL на клиенте через отдельный tRPC-вызов перед каждым рендером `<img>`/`<a>`  | Лишний round-trip до рендера медиа на каждой странице, сложнее кэшировать в браузере/CDN, не работает как обычный `<a href>`/`<img src>` без JS (см. требование в `CLAUDE.md` — страница урока должна корректно отображаться без JavaScript). Прокси-эндпоинт с 302 работает как обычная ссылка.                    |

## Последствия

- Каждый GET файла — это один запрос к БД (RLS-проверка) и один вызов `presignDownload` (без сетевого похода к S3, presign — чисто криптографическая операция подписи URL). Дополнительная задержка минимальна.
- `Cache-Control: private, max-age=60` позволяет браузеру переиспользовать редирект короткое время без полного протухания presigned-ссылки (300 сек), но не даёт публичным/промежуточным кэшам отдавать чужой файл.
- Все места, строившие URL из `key` напрямую (`apps/web/lib/file-url.ts` и его вызовы в блок-редакторе, карточке курса, форме настроек курса, рендере уроков), переведены на `getFileUrl({ id })`, возвращающий `/api/files/<id>`.
- `StorageAdapter` получает новый метод `presignDownload`, реализованный в `S3StorageAdapter` через `@aws-sdk/s3-request-presigner` (`GetObjectCommand`); интерфейс остаётся провайдер-агностичным, как и остальные методы адаптера.
