# Парта5 — senior + product ревью и оценка жизнеспособности

Дата: 2026-07-15. Основание: полный аудит кодовой базы (v0.2.0-phase1, 66 коммитов) + анализ живой БД Moodle «Профспецресурс» (проект psr, sel1).

---

## 1. Вердикт жизнеспособности

**Продукт жизнеспособен, и путь до первого реального запуска короче, чем предполагает текущий роадмап.**

- **Код** — качественный фундамент: strict TypeScript без единого `any`/`@ts-ignore`, корректный edge-safe Auth.js split, настоящая RLS-мультитенантность, работающий блочный редактор (12 типов) и полный self-hosted видео-конвейер (FFmpeg → HLS → HLS.js). Это не прототип-макет, а рабочий MVP контентной части.
- **Но это ещё не LMS.** Оценивание — квизы, задания, журнал оценок — отсутствует полностью (ни моделей, ни кода). Без него продукт нельзя ни продать, ни наполнить реальным контентом из Moodle.
- **Стратегия** (01-analysis-and-plan.md) продумана и внутренне консистентна: open-core под MPL 2.0, B2G через реестр ОВП, отстройка от Moodle по self-host-простоте и AI. Слабое место стратегии — не рынок, а исполнение: вся дифференциация (импорт из Moodle, ЕСИА, родительский кабинет, AI) лежит в ненаписанных фазах 2–7.
- **Разрыв «документация vs код»**: README заявляет LTI 1.3 / SCORM / H5P / импорт Moodle как поддерживаемые стандарты, `_SUMMARY.md` описывает `packages/quiz` — ничего из этого не существует. Для open-source проекта это репутационный риск №1: первый же посетитель GitHub это увидит.

### Можно ли запуститься, импортировав Профспецресурс? Да — и это на редкость удачный кейс

Анализ живой БД PSR (Moodle 5.0.6, sel1, 2033 пользователя, 106 курсов, 4974 зачисления):

| Модуль Moodle      | Кол-во | Судьба при импорте в Парта5    |
| ------------------ | ------ | ------------------------------ |
| quiz               | 2954   | → Quiz (нужен Этап B)          |
| resource (файлы)   | 1011   | → FILE-блок (модель уже есть)  |
| qbank              | 88     | → QuestionBank (Этап B)        |
| forum              | 75     | пропуск с отчётом (объявления) |
| supervideo         | 21     | → VIDEO_EMBED                  |
| label / url / page | 9      | → TEXT / VIDEO_EMBED           |

Типы вопросов: **62 940 из 62 942 — multichoice** (плюс 2 shortanswer). Файлы: 773 PDF (13 ГБ), 224 doc/docx/rtf; всё файлохранилище — 22,4 ГБ.

Выводы:

1. **Полный квиз-движок на 7–8 типов вопросов для запуска не нужен.** Multichoice (single/multi) покрывает 99,997% контента PSR. Остальные типы — итеративно после пилота.
2. Импортеру достаточно поддержать 4 маппинга (quiz, resource, page/label, url/supervideo), чтобы перенести >99% активностей.
3. PSR законсервирован (последний вход 13.03.2026) — **безрисковый пилот**: некому мешать, есть полный SSH/админ-доступ, ежедневные бэкапы, и реальный заказчик (Александр Белый), которому можно показать «ваш Moodle, но современный».
4. **Продакт-инсайт:** ПрофСпецРесурс — это ДПО/профобучение (охрана труда и т.п.), не школа 5–11. Первый реальный кейс сам подсказывает расширить позиционирование: «школы + УДО + ДПО». Сегмент ДПО платёжеспособнее школ и без гос-закупочных барьеров — стоит зафиксировать в стратегии как второй beachhead, а не как случайность.

Оценка пути до пилота с импортированным контентом: **~6–10 недель** конвейером младших моделей (Sonnet) с ревью — при условии последовательности Этапов A→B→C→D из `docs/SUPERPLAN.md`.

## 2. Senior-ревью кода

Масштаб: ~80 TS/TSX файлов; web ~4800 строк, tRPC-слой ~1350, worker ~210, db ~880. Общая гигиена отличная (ESLint/Prettier/husky, Conventional Commits, CI с e2e).

### Блокеры продакшена

**S1. RBAC отсутствует на уровне API.** `apps/web/server/trpc/init.ts` даёт только `publicProcedure` и `protectedProcedure` (= любой залогиненный). Ни одна мутация course/module/lesson/block не проверяет роль или владение курсом. **STUDENT может создавать, редактировать, удалять и публиковать любые курсы своей школы.** RLS изолирует школы, но внутри школы авторизации нет — RLS ошибочно принята за authorization. Нужны `teacherProcedure`/`adminProcedure` + ownership-проверки в `course.ts` и ниже.

**S2. RLS не покрывает 4 таблицы.** Политики есть только на Course/Module/Lesson/ContentBlock/Enrollment (`packages/db/prisma/migrations/20260525213546_add_rls/`) + LessonCompletion. **BlockView, FileAsset, VideoAsset, LearningEvent** имеют `schoolId`, но без политик; при этом `video.ts`, `events.ts` и `services/learning-events.ts` ходят мимо `withTenant()` голым prisma-клиентом. Изоляция держится на ручных `where: { schoolId }` — один забытый фильтр = межтенантная утечка.

**S3. Postgres работает от суперпользователя.** В docker-compose приложение подключается ролью-владельцем БД. `FORCE ROW LEVEL SECURITY` заявлен в ADR-002, но смысл теряется без непривилегированной app-роли. `_SUMMARY.md` утверждает «приложение использует non-superuser роль в prod» — в compose этого нет.

**S4. docker-compose: сервис `web` не получает S3/MinIO и Redis env** (их получает только `worker`). В заявленном сценарии «школа делает `docker compose up` и работает» загрузка файлов/видео и постановка задач из веба сломаны.

**S5. Управления пользователями нет.** Единственные пути: self-signup (создаёт школу + SCHOOL_ADMIN) и self-enroll в **любой** курс по UUID, включая DRAFT, с захардкоженной ролью STUDENT (`enrollment.ts`). Ни создать учителя, ни импортировать ростер, ни зачислить класс — реальную организацию не завести без прямого SQL. Для пилота PSR (2033 пользователя) это блокер наравне с квизами.

### Существенные замечания

- `ctx.session.user.schoolId!` — non-null assertion повсюду; пользователь с `schoolId = null` (SUPER_ADMIN, PARENT — схема допускает) ломает инъекцию RLS-переменной.
- `role` в сессии типизирован как `string`, не `UserRole` — stringly-typed проверки без compile-time защиты.
- Slug-генерация в `course.create` через `count()` — гонка + коллизия после удаления курса; unique constraint выстрелит как raw 500.
- Воркер: без `attempts`/`backoff` у продьюсера, без timeout/concurrency; один тяжёлый/битый файл вешает единственный воркер. FFmpeg рендерит все качества одной командой — нет защиты по времени/памяти.
- Dev-страницы `test-upload`/`test-video` внутри аутентифицированной группы — убрать из прода.
- Redis наружу `6379:6379` без пароля, MinIO-консоль наружу; нет reverse-proxy/TLS в compose; бэкапов томов нет.
- TD-001 (docs/TECH-DEBT.md): `block.create` принимает loose `z.record` вместо discriminated union — чинить до квиз-роутеров.

### Тесты

- Unit: 4 файла (storage, video/embed, file-validation). **tRPC-роутеры, progress-логика, RLS-изоляция — ноль тестов.** Vitest не запускается в CI (только typecheck+build+Playwright).
- E2E: auth и teacher happy-path хорошие; `student-journey.spec.ts` фактически не проверяет ничего (skip + мягкие ассерты «не 404»).
- **Нет ни одного негативного authz-теста** — ровно та область (S1), которая сломана.

## 3. Продакт-ревью

**Сильное:** ясная отстройка от Moodle (не копировать UX — соблюдается), верные ADR (RLS, self-hosted видео без SaaS-зависимостей — прямое попадание в 152-ФЗ и автономность школ), блочный редактор реально удобнее Moodle-форм, монорепо-дисциплина позволяет конвейер младших моделей.

**Риски и что менять:**

1. **Оценивание — не фича, а порог входа.** Реальный контент (PSR: 74% активностей — тесты) без квиз-движка непереносим. Phase 2 должна была идти до «полировки» видео; сейчас это главный долг.
2. **Родительский кабинет «обязателен в MVP»** (01-analysis-and-plan.md, п. 2.5) — для сегмента ДПО не нужен вовсе. Рекомендация: перевести в фазу гос-сегмента (Этап G), MVP-критерием сделать «курс с тестами проходим от начала до конца с оценкой».
3. **Позиционирование**: добавить ДПО/профобучение как сегмент; PSR — готовый референс-кейс «мигрировали с Moodle 5.0 за N дней».
4. **README врёт о стандартах** — заменить «Поддерживаемые стандарты» на «В дорожной карте». Open-source доверие дороже красивого списка.
5. **Демо мертво для посетителя**: демо-курс в DRAFT, публикация требует ручных действий с обложкой. Первое впечатление «ничего нет». Сид должен создавать опубликованный курс.
6. Пилот-школа в Карелии не найдена, GitFlic-зеркало не создано, ИП/товарный знак не оформлены — организационные пункты из «сделать сейчас» стоят с мая.

## 4. Приложение: как проверялись цифры PSR

```bash
# состав активностей
ssh sel1 'docker exec psr-mariadb-1 sh -c "mysql -uroot -p\"\$MYSQL_ROOT_PASSWORD\" sdoprof -e \
  \"SELECT m.name, COUNT(*) FROM mdl_course_modules cm JOIN mdl_modules m ON m.id=cm.module GROUP BY m.name;\""'
# типы вопросов
... "SELECT qtype, COUNT(*) FROM mdl_question GROUP BY qtype;"
# файлы
... "SELECT mimetype, COUNT(*), ROUND(SUM(filesize)/1048576) FROM mdl_files WHERE component='mod_resource' AND filename<>'.' GROUP BY mimetype;"
```

Доступ и runbook PSR: `~/Obsidian/1-projects/psr/` (\_SUMMARY.md, OPERATIONS.md).
