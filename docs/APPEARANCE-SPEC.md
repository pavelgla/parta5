# Спека: внешний вид — брендирование школы и публичная витрина

**Дата:** 2026-07-30. **Контекст:** пилот ПСР (psr.parta5.ru) наполнен и работает, но выглядит как
«парта5»: слушатель видит чужой бренд, синюю ссылку `парта5` в шапке, белую заглушку на `/`,
никакого футера и никаких контактов. В Moodle заказчика (moodle.console10.ru, тема eguru) есть
логотип, фирменный синий, футер с реквизитами и телефоном.

Цель этапа — сделать так, чтобы Парта5 у любой школы выглядела как **её собственная** система,
и чтобы каталог курсов был виден до логина.

## 2. Текущее состояние кода

- `School` (`packages/db/prisma/schema.prisma:92`) — только `slug`, `name`, `kind`. Ни логотипа, ни
  цвета, ни контактов.
- «парта5» захардкожено в `apps/web/app/layout.tsx:7` (metadata), `app/page.tsx:7`,
  `components/site-header.tsx:18`.
- Футера нет вообще. Отдельного лейаута кабинета нет — всё под корневым `app/layout.tsx`.
- Публичные роуты: только `/`, `/login`, `/signup` (matcher в `middleware.ts` защищает
  `/admin`, `/courses`, `/learn`). `/` — заглушка «Парта5 — open-source LMS».
- Картинки отдаются через `app/api/files/[fileAssetId]/route.ts` — **требует сессию**, поэтому на
  публичных страницах обложки курсов не покажутся без правки.
- Школа определяется только из сессии (`tenantProcedure`, `server/trpc/init.ts:32`). Для страниц без
  логина резолва школы нет.
- RLS: доступ к данным школы — через `withTenant(schoolId, fn)` (`packages/db/src/with-tenant.ts`).
- Импортёр создаёт модуль на каждую секцию Moodle, даже пустую (`packages/importer/src/import-course.ts:157`),
  и студент видит пустые разделы (`app/(app)/learn/[courseId]/page.tsx:56`).

## 3. Что делаем

### 3.1 Брендирование как настройка школы (не костыль под ПСР)

Поля в `School`:

| Поле              | Тип             | Назначение                                                                     |
| ----------------- | --------------- | ------------------------------------------------------------------------------ |
| `displayName`     | String?         | Что показывается вместо «парта5» (СДО ПРОФСПЕЦРЕСУРС)                          |
| `legalName`       | String?         | Полное наименование юрлица — строка под логотипом в футере                     |
| `domain`          | String? @unique | Хост публичной витрины (`psr.parta5.ru`) — по нему резолвится школа без сессии |
| `brandColor`      | String?         | HEX, `#2B4E84`. Валидация `^#[0-9a-fA-F]{6}$`                                  |
| `logoFileAssetId` | String? uuid    | Логотип, ссылка на `FileAsset`                                                 |
| `tagline`         | String?         | Подзаголовок на витрине                                                        |
| `contactAddress`  | String?         |                                                                                |
| `contactPhone`    | String?         |                                                                                |
| `contactEmail`    | String?         |                                                                                |
| `siteUrl`         | String?         | Ссылка на основной сайт организации                                            |
| `footerLinks`     | Json?           | `[{ "title": "О нас", "url": "https://…" }]`, максимум 8                       |

Резолв текущей школы — `apps/web/lib/school-context.ts`:

1. есть сессия → `session.user.schoolId`;
2. иначе — `School.domain` = хост запроса (без порта, регистр не важен);
3. иначе — если школа в базе ровно одна, она (типовой self-host);
4. иначе — `null` (показываем нейтральный бренд «Парта5»).

Обёрнуто в `cache()`, чтобы за рендер был один запрос.

Админка: `/admin/settings` — форма (`adminProcedure`: `school.get` / `school.update`), загрузка
логотипа существующим `components/file-upload.tsx`.

Применение бренда: цвет — CSS-переменная `--brand` на `<body>`, компоненты используют
`bg-[var(--brand)]`; шапка — логотип или `displayName`; футер — новый компонент; `<title>` —
`displayName`; страница входа — логотип над формой и кнопка фирменного цвета.

### 3.2 Публичная витрина

- `/` — лендинг школы: шапка, герой (логотип, название, tagline, фон фирменного цвета), сетка
  до 12 опубликованных курсов, кнопка «Все курсы», футер.
- `/catalog` — полный каталог опубликованных курсов с поиском по названию.
- `/catalog/[courseId]` — карточка курса: обложка, название, описание, список названий модулей,
  кнопка «Войти, чтобы учиться» (для гостя) / «Перейти к курсу» (для залогиненного слушателя).
- Данные — `publicProcedure`, школа из хоста, чтение через `withTenant`. Отдаём **только**
  `status = PUBLISHED`.
- `app/api/files/[fileAssetId]` — разрешить анонимный GET, если ассет является логотипом школы либо
  обложкой опубликованного курса. Всё остальное — как сейчас, только по сессии.

### 3.3 Пустые разделы

- Студенту (`learn/[courseId]`) не показывать модули без уроков.
- Импортёр не создаёт модуль для секции без уроков.
- Данные не чистим: правка на уровне UI действует сразу для 12 уже импортированных курсов и
  обратима. Преподаватель в редакторе курса пустые модули по-прежнему видит.

## 4. Риски

- **RLS.** Публичные запросы идут без сессии — обязательно через `withTenant(schoolId, …)`, иначе на
  проде (роль `parta5_app`) вернётся пусто. В деве это не проявится: там суперпользователь.
- **Утечка через `/api/files`.** Ослабление проверки должно быть строго ограничено логотипом и
  обложками опубликованных курсов, иначе публичный доступ ко всем файлам школы.
- **`domain` в мультитенанте.** Пока один инстанс = одна школа; поле `unique`, пустое у остальных.
- **Tailwind v4.** `aspect-video` в этой сборке не работает (см. память проекта) — пропорции задавать
  через `padding-top`/`absolute inset-0`, как в `course-card.tsx`.

## 5. Приёмка

- `pnpm exec turbo run build test --force` — зелёное.
- Живой осмотр в браузере: `/`, `/catalog`, `/catalog/[id]`, `/login`, `/learn/[id]` — с логотипом,
  цветом и контактами ПСР; гость видит каталог и не видит непубличных курсов.
- Курс с пустыми секциями: слушатель не видит пустых разделов, преподаватель видит.
